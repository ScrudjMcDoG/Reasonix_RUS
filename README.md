# Русификатор для Reasonix (desktop)

Локализация интерфейса Reasonix на русский язык: **3960 строк** интерфейса в **36 файлах**
сборки. Перевод встраивается прямо в файлы приложения, установка и откат — одной командой.

Проверено на версии Reasonix: **v1.39.11** (патч привязан к контрольным хэшам файлов этой
сборки; см. «Обновления Reasonix» ниже).

## Скачать

Готовый архив для текущей сборки — на странице
[**Releases**](https://github.com/ScrudjMcDoG/Reasonix_RUS/releases): распакуйте и запустите
`Применить русификатор.cmd`. В архиве нет ни исполняемых файлов Reasonix, ни его данных —
только скрипты локализации и переводы.

---

## Как это работает

В Reasonix есть только три языка интерфейса: `en`, `zh`, `zh-TW` (и бэкенд на Go принимает
для настройки языка строго `auto|en|zh`). Поэтому русификатор занимает **слот английского
языка**: английские строки интерфейса заменяются русскими.

Что из этого следует:

| Настройка языка | Результат |
|---|---|
| Авто (системный) | русский интерфейс (для любой системы, кроме китайской) |
| «English» (в списке теперь подписан **«Русский»**) | русский интерфейс |
| «中文» | китайский интерфейс, как и раньше |

Дополнительно переводятся форматы даты, времени и чисел (`ru-RU`), подписи в панели браузера,
автоматизации (Heartbeat), статистика использования, диагностика, очередь входящих, подсказки
настроек провайдеров и т. д.

## Что остаётся английским

* **CLI/TUI** (`reasonix-cli.exe`) — его строки вкомпилированы в бинарник Go, текстовый
  интерфейс русификатор не затрагивает.
* Названия провайдеров, моделей, продуктов и технические идентификаторы
  (`DeepSeek`, `OpenCode Go`, `MCP`, `JSON`, `bash`, `pwsh`, `JetBrains Mono`, пути к файлам).
* Демонстрационные (mock) записи и служебные сообщения в консоли разработчика.
* Язык ответов модели настраивается отдельно: `reasoning_language` в
  `%APPDATA%\reasonix\config.toml` принимает только `auto|zh|en`. На русском модель отвечает,
  если вы пишете по-русски; жёстко задать язык ответов можно через `system_prompt` в разделе
  `[agent]` того же файла.

## Требования

* Windows 10/11.
* **Node.js 18+** (проверено на Node 26). Если `node` не в PATH, лаунчер поищет его в
  `%ProgramFiles%\nodejs`, `%LOCALAPPDATA%\Programs\nodejs` и в каталогах nvm.
* Reasonix **полностью закрыт** (включая значок в трее) на время установки.
* Права на запись в папку установки Reasonix
  (`%LOCALAPPDATA%\Programs\Reasonix\versions\<версия>\app\resources\app`). Обычно права
  пользователя достаточно, администратор не нужен.

## Установка

1. Закройте Reasonix полностью (меню значка в трее → выход).
2. Запустите **`Применить русификатор.cmd`** (двойной клик).
   Скрипт сам найдёт активную версию Reasonix по `current.json`.
3. Запустите Reasonix. Интерфейс будет на русском.

Перед изменением каждого файла создаётся резервная копия, поэтому откат возможен в любой момент.

## Откат

Запустите **`Откатить русификатор.cmd`** — все 36 файлов вернутся к оригиналу
(целостность проверяется по SHA-256).

## Проверка состояния

**`Проверить состояние.cmd`** показывает по каждому файлу: `оригинал`, `изменён` или `неизвестно`.

---

## Командная строка

Все действия доступны напрямую:

```powershell
# применить (папка определяется автоматически из current.json)
node tools\russianize.mjs apply

# применить в конкретную папку
node tools\russianize.mjs apply --target "C:\Users\Вы\AppData\Local\Programs\Reasonix\versions\v1.39.1\app"

# посмотреть, что будет изменено, ничего не записывая
node tools\russianize.mjs apply --dry-run

# состояние и откат
node tools\russianize.mjs check
node tools\russianize.mjs restore
```

Резервные копии: `ru\backup\<hash-папки-приложения>\` рядом с `meta.json`
(в нём — список файлов и их исходные хэши).

## Структура

```
Применить русификатор.cmd      запуск установки
Откатить русификатор.cmd       возврат оригинала
Проверить состояние.cmd        отчёт о состоянии
ru\                            данные локализации
  units\                       по юнитам: *.en.json (источник) и *.ru.json (перевод)
  units\manifest.json          где в сборке лежит каждый словарь
  manual-patches.json          точечные правки (форматы дат, «хардкод»-строки)
  expected-hashes.json         SHA-256 оригинальных файлов v1.39.1
  version.json                 сводка сборки
  backup\                      резервные копии оригиналов
tools\                         скрипты (русификатор и вспомогательные утилиты разработки)
work\                          рабочие материалы: извлечение строк, отчёты, тестовая копия
```

## Что именно патчится

* **Базовый словарь интерфейса** (`i18n-*.js`) — 3585 строк: панели, настройки, диалоги,
  ошибки, подсказки, горячие клавиши, статистика.
* **Локальные словари чанков**: автоматизации (`HeartbeatPanel`), настройки провайдеров
  (`SettingsPanelEntry`), статистика использования (`UsageStatsPanel`), браузер
  (`BrowserPanelEntry`), очередь входящих (`ComposerInboxQueue`), диагностика
  (`DiagnosticsSettingsPage`), восстановление доступа (`AuthenticationRecoveryActions`),
  подсказки очереди (`ComposerGuidanceShelf`), общие подписи управления (`managementLocale`),
  сообщения входящих (`index`).
* **Точечные правки** (149, из них 120 шаблонов в `ru\manual-patches.json`): русские форматы даты/времени/чисел, подписи кнопок панели браузера,
  названия пресетов вьюпорта, длительности, `lang="ru"` в `index.html`, описания провайдеров.

## Обновления Reasonix

Reasonix устанавливает новые версии в отдельные папки (`versions\vX.Y.Z`) и переключает
активную версию через `current.json`. После обновления:

1. русификатор пропадёт (новая версия — оригинальная);
2. запустите `Применить русификатор.cmd` снова.

Патчер находит словари заново по содержимому (имена файлов и смещения меняются от версии к
версии), поэтому обычно этого достаточно. Если словарь всё же не найден, в отчёте появится
строка «Пропущено», и данные локализации нужно пересобрать под новую сборку — это делает
конвейер в `tools/`:

```powershell
$APP = "C:\Users\<вы>\AppData\Local\Programs\Reasonix\versions\vX.Y.Z\app"

# 1. извлечь словари новой сборки
node tools\reextract.mjs "$APP" work\update

# 2. перенести готовые переводы (по содержимому) и получить список новых строк
node tools\update-translations.mjs            # -> work\update\todo.json

# 3. перевести только новые строки: work\update\new-translations.json
#    (формат: { "<unit>": { "<ключ>": "<русский текст>" } })
# 4. перенести данные в ru\ и пересчитать хэши сборки
node tools\promote-update.mjs "$APP"
node tools\build-data.mjs "$APP"

# 5. применить и проверить
node tools\russianize.mjs apply
node tools\verify.mjs "$APP"
```

Так уже перенесены обновления v1.39.1 → v1.39.8 → v1.39.11: из 3960 строк заново
переводились 15 и 26 новых соответственно — остальное подхватилось автоматически по
содержимому строк.

Если после обновления в отчёте появилась строка «Пропущено» для какой-то точечной правки,
значит бандлер переименовал служебную переменную, и шаблон в `ru\manual-patches.json`
перестал совпадать. Лечится так: найти изменившийся фрагмент, переписать шаблон так, чтобы он
не зависел от односимвольных имён (`tools\show-context.mjs` показывает контекст,
`tools\stabilize-patches.mjs` — пример такой правки).

## Диагностика

* **`[ERROR] Node.js not found`** — установите Node.js LTS и запустите снова.
* **`[WARN] Reasonix is running`** — закройте приложение полностью (в том числе из трея).
* **«Приложение уже русифицировано»** — сначала выполните откат, затем применяйте заново
  (либо `--force`, если нужно перезаписать перевод).
* **Пропущенные словари** в отчёте — файл сборки изменился; напишите, и данные локализации
  будут обновлены под новую версию.
* Пустой/белый экран после установки — запустите `Откатить русификатор.cmd`: это вернёт
  оригинальные файлы (весь патч — текстовый, бинарники не затрагиваются).

## Релизы

Готовые архивы публикуются в
[Releases](https://github.com/ScrudjMcDoG/Reasonix_RUS/releases) — тег совпадает с версией
Reasonix, для которой собран русификатор.

Собрать и опубликовать архив новой версии:

```powershell
$APP = "...\versions\vX.Y.Z\app"          # папка установленной версии (с resources\app)

# 1. данные локализации (см. «Обновления Reasonix»)
node tools\reextract.mjs "$APP" work\update
node tools\update-translations.mjs
#   ... перевод новых строк -> work\update\new-translations.json
node tools\promote-update.mjs "$APP"
node tools\build-data.mjs "$APP"

# 2. архив из отслеживаемых файлов
$stage = "dist\Reasonix_RUS-vX.Y.Z"
New-Item -ItemType Directory -Force -Path $stage | Out-Null
git ls-files | ForEach-Object {
  $d = Join-Path $stage $_
  New-Item -ItemType Directory -Force -Path (Split-Path $d -Parent) | Out-Null
  Copy-Item $_ $d -Force
}
Compress-Archive -Path $stage -DestinationPath "dist\Reasonix_RUS-vX.Y.Z.zip"

# 3. тег и релиз
git tag -a vX.Y.Z -m "Русификатор для Reasonix vX.Y.Z"
git push origin main --follow-tags
$env:GH_TOKEN = "<токен с правом repo>"
node tools\publish-release.mjs --zip "dist\Reasonix_RUS-vX.Y.Z.zip" --tag vX.Y.Z
```

`tools\publish-release.mjs` подставит версию и цифры из `ru\version.json`, добавит SHA-256
архива в описание и заменит ассет, если релиз с таким тегом уже существует.

## Безопасность

* Изменяются только текстовые JS-файлы веб-слоя (`resources\app\assets\*.js`) и `index.html`.
  Исполняемые файлы, `app.asar`, настройки и данные сессий не трогаются.
* Каждый файл перед записью копируется в `ru\backup\...`, откат — побайтовое восстановление
  из резервной копии.
* Оригинальные переводы `zh`/`zh-TW` остаются в сборке нетронутыми.

## Приватность

В репозитории нет ни абсолютных путей с именем пользователя, ни локальных адресов, ни токенов:
инструменты находят установленную версию Reasonix сами (по `current.json` в
`%LOCALAPPDATA%\Programs\Reasonix`) или принимают путь аргументом — см.
[tools/appdir.mjs](tools/appdir.mjs). Проверка выполняется скриптом
[tools/audit-env.mjs](tools/audit-env.mjs):

```powershell
git ls-files > files.txt
node tools\audit-env.mjs files.txt
```

## Происхождение данных

Репозиторий не связан с разработчиками Reasonix и не содержит ни исполняемых файлов
приложения, ни `app.asar`. В нём только инструменты локализации и файлы переводов, включая
извлечённые из приложения английские строки интерфейса (`ru\units\*.en.json`) — они нужны
патчеру для проверки целостности словарей и для переноса локализации на новые версии.
Права на само приложение Reasonix принадлежат его правообладателю.
